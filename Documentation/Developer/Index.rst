=========
Developer
=========

This chapter gives an overview of how the extension is implemented, for
anyone extending or maintaining it.

..  contents:: Table of contents
    :local:

.. _developer-overview:

Overview
========

A short URL is always a regular :sql:`sys_redirect` record with
``redirect_type = short_url`` and ``creation_type = 1``, pointing to the
page via a ``t3://page?uid=<pageId>`` target. The actual unique short path
is generated by TYPO3's own
:php:`\TYPO3\CMS\Redirects\Service\ShortUrlService::generateUniqueShortUrlPath()`.
Both entry points described below insert this record the same way and both
call :php:`RedirectCacheService::rebuildForHost()` afterward so the redirect
is picked up immediately.

.. _developer-button:

:php:`AddShortUrlButton`
=========================

:php:`UEBERBIT\Shorturls\EventListener\AddShortUrlButton` is a PSR-14
listener on :php:`\TYPO3\CMS\Backend\Template\Components\ModifyButtonBarEvent`
(registered via the :php:`#[AsEventListener]` attribute). For the page
currently opened in the page module it:

#.  Bails out early if no page ID is present, or the page's ``doktype``
    (looked up separately, since it is not part of the button bar event) is
    not allowed by :confval:`shorturls_button_doktypes`.
#.  Bails out if the page has ``is_siteroot`` set and
    :confval:`shorturls_button_on_siteroot` is disabled.
#.  Looks up an existing short URL redirect for the page.
#.  Renders either a "create" link (pointing at the ``shorturls_create``
    backend route) or a "copy to clipboard" link, using
    ``data-shorturl-*`` attributes that are picked up by the frontend module
    described below.

.. _developer-doktype-configuration:

:php:`DoktypeConfiguration`
=============================

:php:`UEBERBIT\Shorturls\Configuration\DoktypeConfiguration::getAllowedDoktypes()`
is the shared helper both :php:`AddShortUrlButton` and
:php:`AutoGenerateShortUrlHook` use to read a doktype-multiselect site
configuration value (:confval:`shorturls_button_doktypes` and
:confval:`shorturls_auto_generate_doktypes`). It accepts both shapes the
value can have: an array of value strings (what the backend saves, e.g.
``['1', '254']``) and a comma-separated string (convenient for hand-written
:file:`config.yaml`). A missing key falls back to only the default page
type (``1``, Standard page).

.. _developer-hook:

:php:`AutoGenerateShortUrlHook`
=================================

:php:`UEBERBIT\Shorturls\Hooks\AutoGenerateShortUrlHook` is a classic
DataHandler hook, registered in :file:`ext_localconf.php` via
``$GLOBALS['TYPO3_CONF_VARS']['SC_OPTIONS']['t3lib/class.t3lib_tcemain.php']['processDatamapClass']``
and implementing ``processDatamap_afterDatabaseOperations()``. It only acts
on newly created ``pages`` records, and:

#.  Reads :confval:`shorturls_auto_generate` from the page's site
    configuration; bails out if disabled.
#.  Reads :confval:`shorturls_auto_generate_doktypes` (falling back to only
    the default page type, ``1``) and compares it against the ``doktype``
    of the new page (taken from the ``$fieldArray`` passed to the hook).
#.  Bails out if the new page has ``is_siteroot`` set (also taken from
    ``$fieldArray``) and :confval:`shorturls_button_on_siteroot` is disabled.
#.  Creates the short URL redirect exactly like
    :ref:`developer-controller`, unless one already exists.

..  note::
    A newly created page with ``is_siteroot`` set is not necessarily part
    of the site that :php:`SiteFinder::getSiteByPageId()` would otherwise
    resolve to: TYPO3 falls back to an auto-generated, unconfigured site
    for such a page unless a real site configuration already exists for
    it (as is the case for a nested subsite's root page). In that fallback
    case, :confval:`shorturls_auto_generate` is already off by default, so
    no short URL is created regardless of :confval:`shorturls_button_on_siteroot`.

.. _developer-controller:

:php:`ShortUrlController`
===========================

:php:`UEBERBIT\Shorturls\Controller\ShortUrlController::createAction()`
is registered as the backend route ``shorturls_create`` (see
:file:`Configuration/Backend/Routes.php`). It is called when an editor
clicks the "create" link rendered by :php:`AddShortUrlButton`, re-checks
that no redirect exists yet, inserts the ``sys_redirect`` record, adds a
flash message and redirects back to the page module.

.. _developer-doktype-select:

:php:`DoktypeItemsProcFunc`
=============================

:php:`UEBERBIT\Shorturls\Backend\DoktypeItemsProcFunc` is the
``itemsProcFunc`` for both doktype-multiselect site configuration fields
(:confval:`shorturls_button_doktypes` and
:confval:`shorturls_auto_generate_doktypes`). It mirrors the page type
options from
``$GLOBALS['TCA']['pages']['columns']['doktype']['config']['items']`` so the
selectable page types always match the ones available for `pages.doktype`
in this installation (including page types added by other extensions).

..  note::
    The grouping (and its translated group headers) of the "Standard page /
    Link / Special" sections is configured statically alongside this field
    in :file:`Configuration/SiteConfiguration/Overrides/sites.php` via
    ``itemGroups``, not inside the ``itemsProcFunc``. TYPO3 only evaluates
    ``itemGroups`` from the field's static TCA, *after* the
    ``itemsProcFunc`` has run – changes to ``itemGroups`` made from within
    the processor function itself are discarded.

.. _developer-frontend:

Frontend module
================

:file:`Resources/Public/JavaScript/ShortUrlActions.js` is loaded on every
backend page module request via
:file:`Configuration/JavaScriptModules.php`. It listens for clicks on
elements carrying ``data-shorturl-copy`` (copies the value to the clipboard
and shows a notification) or ``data-shorturl-confirm`` (shows a
confirmation dialog before following the link).
